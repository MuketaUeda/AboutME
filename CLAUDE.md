This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

This is Gabriel Rosati's personal portfolio site: a single-page React application (Vite + React 19 + React Router + Tailwind CSS v4) deployed to Vercel.

## Commands

```bash
npm run dev       # start Vite dev server
npm run build     # production build to dist/
npm run preview   # preview the production build locally
npm run lint      # run ESLint over the project
```

There is no test suite configured in this repo.

## Architecture

- **Routing**: `src/App.jsx` defines all routes with `react-router-dom` (`BrowserRouter`/`Routes`/`Route`). Currently two routes: `index` → `Home`, `*` → `NotFound`. New pages go in `src/pages/` and get registered here.
- **Single-page layout**: `src/pages/Home.jsx` stacks all the landing-page sections (`Navbar`, `HeroSection`, `AboutSection`, `SkillsSection`, `ProjectsSection`, `ContactSection`, `Footer`) from `src/components/`. Navigation (`NavBar.jsx`) uses in-page anchor links (`#hero`, `#about`, `#skills`, `#projects`, `#contact`) that match each section's `id`, not router paths — adding a section means adding both a `<section id="...">` block in a component and a matching entry in `navItems` in `NavBar.jsx`.
- **Content-as-data-in-component**: `ProjectsSection.jsx` and `SkillsSection.jsx` hold their content as local arrays (`projects`, `skills`) directly in the component file rather than in a separate data/config file. Skills only carry `name`/`Category` (no arbitrary skill-level percentage — that was intentionally removed). Update projects/skills by editing those arrays in place, including image paths under `public/projects/`.
- **Design system: neobrutalism**: The site uses a neobrutalist visual language — thick 2px solid black borders (`border-2 border-border`), hard non-blurred offset drop shadows (`shadow-shadow`, computed as `4px 4px 0px 0px hsl(var(--border))`), near-zero border radius (`--radius-base: 2px`), and a flat, high-contrast, multi-color palette (no gradients, no opacity-tinted backgrounds like the old `/10`/`/20`/`/70` classes — always solid colors). `.dark` inverts background/foreground/border (cream background/black border in light mode → near-black background/cream border in dark mode) while the brand colors (`--main`, `--accent`, `--chart-1..5`) stay fixed across themes; this also makes `shadow-shadow` automatically flip to a visible cream shadow in dark mode since it's computed from `--border`.
- **UI primitives from neobrutalism-components**: `src/components/ui/` holds `Button`, `Card` (+ subparts), `Badge`, `Input`, `Textarea`, `Label`, `Alert` — adapted from the [neobrutalism-components](https://github.com/ekmas/neobrutalism-components) shadcn-style registry (`https://www.neobrutalism.dev/r/<name>.json`), converted from `.tsx` to plain `.jsx` (types stripped, no TypeScript in this project) and using this project's own token names instead of the registry defaults. When adding another primitive from that library, fetch its registry JSON the same way and strip types the same way — don't hand-roll a new one-off component if the library already has it. `Button`/`Badge` re-export their `cva` variants helper (`buttonVariants`/`badgeVariants`) alongside the component for cases that need the classes without the component itself (e.g. `SkillsSection.jsx`'s filter `<button>`s use `badgeVariants({variant: "neutral"})` directly since `Badge` renders a `<span>`, not a clickable element) — both exports carry an `eslint-disable-next-line react-refresh/only-export-components` since this dual-export pattern trips that rule by design.
- **Theming**: Dark/light mode is handled by `ThemeToggle.jsx` toggling the `dark` class on `document.documentElement` and persisting the choice to `localStorage` under the `theme` key (defaults to dark). Tokens are HSL CSS variables in `src/index.css` under `:root`/`.dark`, mapped into Tailwind's `@theme` — change theme colors there, not by hardcoding hex/rgb classes. Token roles: `--background`/`--foreground`/`--border`/`--ring` (page chrome, inverts per theme), `--secondary-background` (elevated surface color, aliased as `--color-card` so existing `bg-card` usage still works), `--main`/`--main-foreground` (the site's primary action color, used by `Button`'s default variant and anything analogous to the old `--primary`), `--accent`/`--accent-foreground` (semantic, NOT decorative — reserved for AI/ML content: the "AI-powered" hero badge, the `artificial-intelligence` skill category; stays blue across both themes), `--chart-1..5` (5 fixed vibrant hues — yellow/lime/orange/turquoise/red — used for `SkillsSection`'s per-category color coding and the Hero's decorative stickers; `--chart-5` doubles as `--error`), `--success`/`--error` (status banner colors, replacing the old hardcoded `bg-green-50`/`bg-red-50`), `--category-tools`/`--category-infra` (two extra component-scoped colors, only used by `SkillsSection`'s category map, not general brand tokens).
- **Typography**: `--font-display` (Archivo Black) for headings/hero/nav-logo, `--font-sans` (Inter, body default) — only 2 families now (JetBrains Mono was removed). What used to be `font-mono` tags/pills/filter-labels (skill chips, project tags) are now `Badge`/`badgeVariants` instances styled `uppercase tracking-wider font-heading` instead of a monospace face.
- **Hero signature visual**: The Hero no longer has a physics-simulated background (`EmbeddingGraph.jsx` was removed along with its `graph-edge`/`graph-node-dot` utilities). In its place, `HeroSection.jsx` renders 4 static absolutely-positioned "sticker" divs (rotated, bordered, hard-shadowed rectangles in `chart-1`/`chart-2`/`main`/`accent`, hidden below `md:`) around the centered hero text, plus a `text-stamp` utility (hard offset text-shadow duplicate, replacing the old blurred `text-glow`) on the name and nav logo. There is no page-wide decorative background component — motion/decoration stays confined to the Hero's stickers and the existing `fade-in`/`animate-fade-in-delay-*` stagger.
- **Path alias**: `@/` resolves to `src/` (configured in `vite.config.js`). Some files use it (e.g. `@/lib/utils`, all of `src/components/ui/*`), others use relative imports (`./ui/button`) — no strict convention is enforced, but prefer `@/` for new code for consistency with `lib/utils`.
- **`cn()` helper** (`src/lib/utils.js`): combines `clsx` + `tailwind-merge` for conditional/merged Tailwind class strings. Used throughout, including by every `src/components/ui/*` primitive's `className` merging. Use this instead of manual string concatenation when a component has conditional classes.
- **Contact form**: `ContactSection.jsx` submits directly to a Formspree endpoint (`https://formspree.io/f/mwpqrnjq`) via `fetch` — there is no backend in this repo.
- **Static assets**: CV PDFs live in both `cv/` (top-level, linked from `AboutSection.jsx`'s download buttons) and duplicated under `public/projects/`; project screenshots are served from `public/projects/` and referenced with absolute paths (e.g. `/projects/deck.PNG`).
- **Deployment**: `vercel.json` configures Vercel to run `npm run build` and serve `dist/` as a static Vite app.
